# Calc3D — prototipo de calculadora 3D

Para las PR, checks y releases automáticos de versiones, consulta [controles del repositorio](docs/repository-controls.md). Los controles están activos en [GitHub](https://github.com/luismarinoc/calc3d): `main` requiere PR y checks exitosos, también para administradores. El [CI de la carga inicial](https://github.com/luismarinoc/calc3d/actions/runs/39512874793) pasó sin publicar una release; la publicación de una futura PR de versión aún no se ha ejercitado.

En la raíz del proyecto, ejecuta `npm start` y abre http://127.0.0.1:5173. El servidor estándar Python se limita a tu equipo: deténlo con Ctrl+C. Pruebas: `npm test` (pruebas Node, sin navegador). Para pruebas de navegador, instala las dependencias de desarrollo con `npm install` y los navegadores locales con `PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright npx playwright install chromium webkit`; luego ejecuta `npm run test:e2e`. Playwright levanta y detiene su propio servidor local en 127.0.0.1:5173 (el puerto debe estar libre); genera capturas inicial y final de cada proyecto en `test-results/`, excluido de Git. Los proyectos emulan escritorio Chromium, teléfono WebKit y iPad WebKit en vertical/horizontal; no equivalen a pruebas en un dispositivo iOS físico ni en Safari real. No abras `index.html` con `file://`: los módulos ES necesitan HTTP local.

## Compras e inventario adquirido de prueba

Con `npm start`, abre http://127.0.0.1:5173/purchases.html o usa el enlace «Compras e inventario de prueba» en la calculadora. Indica fecha de compra (calendario local, admite fechas históricas), lugar/proveedor, dirección y teléfono opcionales, y una o más líneas con material, marca, color, cantidad entera de bobinas, peso neto en gramos **por bobina** y precio entero CLP **por bobina**; notas opcionales. El límite técnico es 1000 bobinas por compra. La vista previa calcula total y número de bobinas sin guardar. Solo «Guardar compra de prueba» crea una compra y bobinas individuales; después el formulario se limpia para reducir guardados duplicados. El historial muestra fecha, contacto, líneas y total; el inventario muestra ID, procedencia, peso **inicial adquirido** y precio individual. Editar el borrador o recargar no modifica registros anteriores. Errores de lectura/escritura no confirman guardados; si otra pestaña cambió la clave, recarga antes de intentar de nuevo. La detección de conflictos entre pestañas es aproximada, no una transacción atómica.

Compras se guardan únicamente en el `localStorage` de este navegador: **no son base de datos de producción, respaldo ni autenticación**. No descuentan impresiones/consumos y no representan saldo real de existencias. En la calculadora, el selector incluye estas bobinas compradas de prueba junto a dos opciones ficticias. Cada opción comprada conserva un ID estable `purchase:<id de bobina>`, fecha, material, marca y color; debajo se muestran su ID original, compra, precio de adquisición y peso inicial adquirido. Al elegirla se completan el precio y el peso, de solo lectura; las bobinas ficticias siguen siendo editables. Los gramos estimados pueden superar el peso inicial: no se comprueban existencias ni se descuenta inventario al simular o guardar una cotización. Una compra ilegible no se sobrescribe: la calculadora sigue permitiendo usar bobinas ficticias y muestra un aviso. Una copia guardada cuyo ID comprado ya no se encuentra muestra error en vez de reemplazarlo por una bobina ficticia; el historial original no cambia. Recarga la página para actualizar el catálogo, sin sincronización entre pestañas. `evaluate(form, catalog)` admite un catálogo opcional creado con `buildSpoolCatalog(purchaseStore.listSpools())`; sin segundo argumento mantiene solo las opciones ficticias y el error existente para ID desconocido. Para probar solo el mapeo de formulario: `node --test tests/purchase-form.test.mjs`; para el recorrido de navegador: `npm run test:e2e -- tests/e2e/purchases.pw.mjs`; las suites completas siguen siendo `npm test` y `npm run test:e2e`.

La pestaña «Calculadora» reúne campos, resumen en vivo y Guardar en una sola vista compacta de escritorio (objetivo 1280×800 sin scroll en el borrador normal). «Historial» abre los registros locales por separado; usa las flechas izquierda/derecha, Inicio/Fin o un clic para cambiar de pestaña. Guardar confirma en la calculadora sin cambiar de vista. «Abrir copia» vuelve a la calculadora y no escribe ni modifica el registro; en pantallas pequeñas, con costos adicionales expandidos o zoom, desplázate normalmente para alcanzar todos los campos. No se ocultan los avisos ni errores.

La interfaz en español usa CLP y muestra bobinas **ficticias** con precios de ejemplo editables y bobinas compradas de prueba con precio y peso adquiridos de solo lectura, costos estimados y precio de venta separado. Incluye venta, uso interno/personal y regalo. Uso interno y regalo conservan el costo sin ingreso ni ganancia y reinician/desactivan los ajustes comerciales; regalo se identifica por separado en el historial. El cobro familiar o parcial queda pendiente de decisión. Los campos numéricos opcionales pueden quedar vacíos (equivalen a cero): horas/minutos, gastos adicionales, ajustes comerciales, costo de reposición e imprevistos. Precio de compra, peso neto, gramos, potencia, tarifa, vida útil y multiplicador personalizado siguen siendo obligatorios cuando corresponden. Los valores no vacíos inválidos se rechazan. En un cálculo nuevo el precio de venta usa multiplicador ×2 por defecto, no margen porcentual. «Ganancia sobre costo (%)» solo se muestra al abrir una copia histórica. Descuento y recargo pueden coexistir como monto CLP o porcentaje independiente sobre el precio base; una venta por debajo del costo se rechaza. El cálculo cambia al editar sin guardar. El botón «Guardar cálculo de prueba» registra una copia explícita con fecha ISO e identificador y «Abrir copia» carga los campos sin alterar el original. El historial usa `localStorage` exclusivamente en este navegador: no es base de datos, backup, autenticación ni autorización. Si el almacenamiento es ilegible no se sobrescribe y si falla la escritura no se confirma el guardado. Nada descuenta inventario, registra una impresión real o constituye venta realizada. No hay imágenes, informes ni cuentas de usuario. IVA y política de cobro familiar siguen sin definirse.

## Cálculo de referencia (nuevo)

El formulario nuevo y cualquier recarga usan el cálculo de referencia directamente, sin selector de versión. Costo de reposición, vida útil, imprevistos y multiplicador están a la vista. Una copia histórica sin modo o con modo anterior se abre con su cálculo original en CLP enteros y muestra un aviso con «Iniciar cálculo actual»: esa acción inicia un borrador nuevo de referencia, sin convertir la copia guardada ni modificar `localStorage`. Abrir y editar una copia tampoco la sobrescribe; solo Guardar crea otro registro. El cálculo de referencia usa precio/peso de la bobina seleccionada, gramos, tiempo, potencia y tarifa eléctrica. Introduce costo de reposición de la máquina y vida útil en horas para el desgaste (`costo / vida × horas`) y porcentaje de imprevistos aplicado únicamente a material + electricidad + desgaste. Mantención, trabajo y otros costos son gastos de producción adicionales explícitos. No se inventan recargos de insumos, comisión de plataforma ni IVA. El modo nuevo presenta centavos; el anterior conserva CLP enteros.

Para venta, selecciona multiplicador ×2 (predeterminado), ×2.5, ×3, ×3.5, ×4, ×5 o personalizado positivo. Es un **multiplicador**, no margen porcentual. Descuento y recargo independientes, en monto o porcentaje del precio base, pueden coexistir; se exige precio final no inferior al costo, ambos comparados en centavos. Uso interno muestra gasto y regalo muestra costo de regalo, ambos sin precio, ingreso ni ganancia y con ajustes comerciales desactivados. Ninguna cotización descuenta stock; solo «Guardar cálculo de prueba» crea una copia local desligada de su formulario.

API pura independiente: `import { calculateReferenceQuote } from './src/domain/reference-costs.mjs'`. Recibe los campos obligatorios `purpose`, `spool`, `grams`, `hours`, `minutes`, `watts`, `electricityPricePerKwh`, `replacementCost`, `replacementLifetimeHours` (>0), `errorPercent` (≥0), y para venta `multiplier` (>0). `purpose` admite `sale`, `internal` y `gift`; el regalo devuelve `giftCost` igual a `totalCost`, precio y ganancia cero. La API pura recibe números (no cadenas vacías); solo el formulario convierte sus campos opcionales vacíos a cero. Los gastos opcionales `maintenancePerHour`, `laborMinutes`, `laborRatePerHour`, `extraProductionCost` y ajustes `discount`/`surcharge` mantienen su significado. Valida números finitos y límites de duración. Conserva precisión en cálculos intermedios y redondea únicamente salidas monetarias a dos decimales: `breakdown` (material, electricity, wear, allowance, maintenance, labor, extras), `totalCost`, `basePrice`, `discountAmount`, `surchargeAmount`, `finalPrice`, `commercialProfit`, `internalCost`. Ejemplo: 22000 CLP/1000 g, 294 g, 11 h, 130 W, 230 CLP/kWh, reposición 220000 CLP/4320 h, imprevistos 5%, ×2: material 6468.00, electricidad 328.90, desgaste 560.19, imprevistos 367.85, costo 7724.94, precio final 15449.88 CLP. Pruebas: `node --test tests/reference*.test.mjs` y pruebas de navegador `tests/e2e/reference-quote.pw.mjs`.

## Contrato del módulo de cálculo anterior

Módulo puro compatible con navegador y Node: `import { calculateQuote } from './src/domain/costs.mjs'`.

```js
const result = calculateQuote({
  purpose: 'sale', // 'sale' o 'internal'
  spool: { purchasePrice: 20000, netWeightGrams: 1000 },
  grams: 50, // consumo total, incluidos soportes y purga
  hours: 1, minutes: 30,
  watts: 200, electricityPricePerKwh: 200,
  markupPercent: 50,
  discount: { type: 'percent', value: 10 },
  surcharge: { type: 'amount', value: 100 },
});
```

Obligatorios: `purpose`, `spool.purchasePrice` (CLP, ≥0), `spool.netWeightGrams` (>0), `grams` (≥0), `hours` (entero ≥0), `minutes` (entero 0–59), `watts` (≥0) y `electricityPricePerKwh` (CLP/kWh, ≥0). Numéricos siempre finitos de tipo número; no se convierten cadenas. Opcionales con valor predeterminado cero: `depreciationPerHour`, `maintenancePerHour` (CLP/h), `laborMinutes`, `laborRatePerHour` (CLP/h), `extraProductionCost` (CLP) y `markupPercent`. `discount` y `surcharge` son opcionales; cada uno acepta `{ type: 'amount' | 'percent', value: número no negativo }`. Descuento máximo 100% o monto máximo igual al precio base. Un recargo porcentual no tiene límite porcentual, pero el resultado debe caber en CLP entero seguro. No se usan existencias remanentes para impedir una estimación y la función nunca modifica datos ni inventario.

`breakdown` presenta `material`, `electricity`, `depreciation`, `maintenance`, `labor`, `extras`; `totalCost` suma estos componentes. Cada componente se redondea al CLP entero más cercano (mitad hacia arriba) **antes** de sumar. `basePrice = round(totalCost × (1 + markupPercent/100))`: es **recargo sobre costo (markup), no margen**. Ambos ajustes porcentuales usan este mismo precio base; cada ajuste se redondea a CLP antes de restar/sumar. El piso se comprueba sobre esos importes enteros; la igualdad con el costo se acepta. `finalPrice`, `commercialProfit`, `internalCost`, `discountAmount` y `surchargeAmount` completan el resultado. En `internal` el costo sigue visible y `internalCost = totalCost`, mientras precio base, precio final y ganancia comercial son cero; el markup se ignora y los ajustes de venta no cero se rechazan. No hay propósito familiar hasta acordar la política de cobro parcial.

Los errores son excepciones con mensajes estables en español: `Propósito inválido: use sale o internal.`, `<campo> debe ser un número finito no negativo.`, `hours debe ser un entero no negativo.`, `minutes debe ser un entero entre 0 y 59.`, `spool.netWeightGrams debe ser un número finito mayor que cero.`, `<ajuste>.type debe ser amount o percent.`, `El descuento porcentual no puede superar 100%.`, `El descuento no puede superar el precio base.`, `El trabajo interno no admite descuentos ni recargos.`, `Resultado fuera del rango seguro de CLP.` y `El precio final no puede ser menor al costo total (faltan N CLP).` Esta política de redondeo es una suposición técnica reversible, no una decisión fiscal; no incluye IVA, tarifas de canal ni importación desde slicer.
