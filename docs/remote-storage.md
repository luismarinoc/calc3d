# Almacenamiento de la aplicación

Las tres pantallas requieren sesión Supabase Auth y membresía Calc3D activa. El administrador ve el enlace «Usuarios»; todas las operaciones de lectura/escritura consultan el acceso antes de invocar REST/RPC, y RLS aplica el aislamiento de registros por UUID. Revocar membresía corta la siguiente operación incluso si la sesión sigue abierta. Si la red falla, recarga para reintentar: nunca se sustituyen los datos remotos por historiales locales.

Los cálculos guardan copias inmutables de formulario, entrada, resultado y datos opcionales del cliente. `calc3d_save_quote` asigna el número secuencial en el servidor. La configuración de impresoras utiliza `calc3d_save_printers` con revisión esperada (CAS); la impresora inicial de ejemplo no crea fila hasta Guardar. Las compras usan `calc3d_save_purchase` para crear compra y bobinas atómicamente; su peso es el inicial adquirido, **no** saldo y no se descuenta al calcular.

No hay importación ni borrado implícito de `localStorage`, no se escriben ejemplos ni se transfieren borradores entre cuentas. El cliente emplea únicamente la URL pública y la clave anon/publishable; nunca credenciales administrativas. Para desarrollo: configura `.env.local` como en [login](login.md), aplica las migraciones de almacenamiento e invitación en el entorno autorizado, ejecuta `npm start` y visita `/`, `/settings.html`, `/purchases.html` o `/login.html`. Para producción: `npm run build`, sirve solamente `dist/` en HTTPS y permite la URL raíz de retorno OAuth en Supabase Auth sin reemplazar las allowlists de otras aplicaciones. No se ha realizado aquí el consentimiento Google ni un despliegue real.
