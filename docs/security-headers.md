# Cabeceras de seguridad de Calc3D

`deploy/security-headers.mjs` exporta `hardenCalc3dTraefik(config, { mode = 'report-only' })`, `calc3dDomainMiddlewares(domain)` y `CALC3D_SECURITY_MIDDLEWARE`. La primera función recibe **un objeto Traefik ya analizado y confiable**, no YAML ni un archivo, y devuelve una copia independiente. La segunda recibe el registro de dominio de Calc3D y devuelve **solo una lista nueva de nombres de middleware**; no modifica el registro ni prepara una petición a Dokploy. Ambas son puras: no leen archivos, escriben, llaman a la red ni aplican configuración. El operador usa sus propias herramientas privadas aprobadas para lectura, análisis, respaldo, serialización y actualizaciones nativas. No cambiar build, Compose, variables de entorno, proxy global ni Auth.

Ejemplo: `const siguiente = hardenCalc3dTraefik(actual); const referencias = calc3dDomainMiddlewares(dominioActual);`. `actual` necesita `http.routers` y `http.services` como objetos; **puede omitir `http.middlewares`**, como la configuración nativa actual. Si existe, debe ser un objeto; `null` o un valor de otro tipo es inválido. La ruta única candidata requiere `rule: 'Host(`calc3d.tbema.net`)'`, `entryPoints` con `websecure`, `tls` y un servicio existente. La segunda función acepta solo el dominio `NrgBtIZ2HgKnLGXKERzNo` del host `calc3d.tbema.net`, Application `YYhCRbv7263_nwsWYnmZv`, tipo `application`, HTTPS habilitado, `customEntrypoint: null` y lista válida de middleware. Conserva el orden y nombres previos, agrega una sola referencia `calc3d-security-YYhCRbv7263` y es idempotente. Si cualquiera de las validaciones falla, detenerse: no aplicar un resultado parcial.

## Preflight y aplicación acotada (operador)

1. Confirmar la Application y el dominio autorizados. Leer **frescos** la configuración Traefik de esa Application y el registro del dominio. Respaldar **ambos** antes de modificar nada. Comparar host, rutas HTTP y HTTPS, servicio, TLS, middleware y metadatos del dominio. Si hubo una edición entre lectura y aplicación, releer y reevaluar: los helpers no controlan concurrencia. No usar una plantilla fija de la configuración de ejemplo.
2. Analizar la configuración actual mediante la herramienta privada disponible. `hardenCalc3dTraefik(actual)` genera la definición Report-Only y agrega la referencia solamente a la ruta HTTPS de Calc3D. Si no existía `http.middlewares`, lo crea **solo en la copia devuelta**. Revisar el diff: se preservan redirect HTTP, TLS, servicios, rutas y middleware previos. `calc3dDomainMiddlewares(dominioActual)` prepara la misma referencia en la lista persistida del dominio, sin perder entradas anteriores. Revisar también esa diferencia. **La edición del archivo de la Application por sí sola no basta como referencia durable**: Dokploy v0.30.7 `domain.update` reconstruye la ruta desde los middleware del registro de dominio. Según el código de esa versión, la ruta HTTP de redirección conserva solo `redirect-to-https`; los middleware del dominio se agregan a la ruta HTTPS en este caso (`customEntrypoint: null`). La definición permanece en la configuración de la Application.
3. Solo tras aprobar ambos diffs, aplicar la **definición** con la actualización nativa de Traefik **de esa Application**. Después persistir la **referencia** mediante `domain.update` del dominio autorizado. Para construir el cuerpo completo permitido por esa operación, el operador debe conservar explícitamente los valores actuales de **host, path, port, HTTPS, certificado, entrypoint, internal path, strip path, auth y enabled**, además del `domainId` requerido y la lista `middlewares` calculada; confirmar los nombres exactos y los campos admitidos en el registro y la interfaz nativa antes de enviar. No omitir esos valores opcionales: algunos tienen defaults del servidor. No enviar `applicationId` como campo de actualización (no está admitido); se usa solo para validar la identidad de entrada. No introducir ACL inseguras, CORS ni cabeceras globales.
4. Releer **ambas** configuraciones después de la actualización de dominio, que puede reconstruir las rutas. Confirmar la definición en la Application, la referencia en el dominio y solamente en la ruta HTTPS, y comprobar públicamente: `Content-Security-Policy-Report-Only`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy: camera=(), microphone=(), geolocation=()` y `Strict-Transport-Security: max-age=300` sin `includeSubDomains` ni `preload`. Comprobar el redirect HTTP, TLS y las rutas ajenas. Las pruebas locales verifican los objetos generados, no el efecto público. No reiniciar Auth.
5. Validar carga real de páginas, recursos, solicitudes a `https://sp-dev.tbema.net` y conexiones `wss://sp-dev.tbema.net`. La política usa origen propio para scripts, estilos, fuentes e imágenes; `connect-src` añade únicamente esos dos destinos. No incluye comodines, `unsafe-inline`, `unsafe-eval` ni `data:` para imágenes sin necesidad demostrada. El modo `enforce` (`hardenCalc3dTraefik(actual, { mode: 'enforce' })`) se reserva para un cambio posterior validado por el propietario: sustituye Report-Only por `Content-Security-Policy`, no activa ambas. Report-Only **no impone** CSP.

## Reversión y límites

Si las cabeceras perjudican Calc3D, registrar evidencia y restaurar **solo** la configuración de Application y el registro de dominio de Calc3D desde los respaldos revisados, confirmando que no hubo cambios intermedios. No afectar otras aplicaciones, middleware compartidos, permisos SQL ni Auth; no restaurar acceso público inseguro. Una ruta ambigua, una referencia externa al middleware reservado o una definición con contenido inesperado exige inspección humana: el módulo falla cerrado.

El readback de ambas configuraciones y las cabeceras públicas siguen pendientes hasta la publicación. **No está comprobada** la persistencia de la configuración personalizada después de futuros redeploys: repetir el readback después de cada despliegue hasta comprobarlo. Tampoco está probado el retorno Google real, que requiere comprobación manual. Estas cabeceras no certifican ausencia de vulnerabilidades del proyecto.
